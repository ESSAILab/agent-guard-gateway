## 核心组件

### 1. 模型调用器（Model Invoker）

位置：`backend/app/services/model_invoker.py`

**职责**：
- 统一封装 REST 与脚本两种接入方式的调用逻辑
- REST：构造请求，按 JsonPath + 状态码判定安全性
- 脚本：在独立子进程中执行用户代码，约定返回格式
- 返回结构化的 `InvokeResult`（safe/unsafe/timeout/error + 耗时）

**隔离机制**：
- REST 调用通过 `httpx` 的异步客户端，配置超时
- 脚本调用在 `asyncio.create_subprocess_exec` 中运行，天然隔离

### 2. 策略引擎（Strategy Engine）

位置：`backend/app/services/strategy_engine.py`

**职责**：执行单条策略编排，实现策略绑定模型的调用规则。当前支持两种规则：顺序检测（sequential）与随机检测（random）。

#### 顺序检测（Sequential）

**流程**：
1. 按策略绑定的检测模型顺序逐个调用
2. 任一模型判定不安全，立即终止并返回不安全
3. 全部模型通过则整体判安全

**优势**：
- **快速失败**：第一个不安全即可终止，降低延迟
- **资源节约**：不触发后续模型调用

**适用场景**：高吞吐要求，优先保证响应速度

#### 随机检测（Random）

**流程**：
1. 从策略绑定的检测模型池中随机挑选 1 个检测能力调用
2. 以被选中模型的判定作为策略整体结果（安全/不安全）
3. 单模型超时仍按策略配置的超时策略（safe/unsafe）计入

**优势**：
- **调用成本低**：每次仅调用 1 个检测模型，延迟与开销确定
- **不确定性防护**：调用方无法预判具体命中的检测能力，提升绕过难度

**适用场景**：模型池中多个检测能力可相互替代，或需要以较低成本进行抽检

### 3. 网关编排（Gateway）

位置：`backend/app/services/gateway.py`

**职责**：
- 按 JsonPath 从用户请求中提取被检测内容
- 按顺序执行 API 路径绑定的策略链
- 任一策略不安全，立即终止并返回不安全
- 全部策略通过，返回安全
- 落库请求日志与检测模型调用日志
- 通过 `broadcaster` 推送实时事件到 WebSocket

**策略链示例**：
- 策略1（个人信息检测）→ 策略2（越狱攻击检测）→ 策略3（不当言论检测）
- 三个策略依次执行，全部安全才放行

### 4. 实时广播器（Broadcaster）

位置：`backend/app/services/broadcaster.py`

**职责**：
- 维护 WebSocket 连接池
- 推送四类事件：`request_received` / `strategy_start` / `strategy_result` / `final_result`
- 供大屏前端消费，展示实时检测流程与顺序检测动画

**事件流**：
```
1. request_received   → 大屏显示请求到达，AI 应用节点闪烁
2. strategy_start     → 策略块出现，展示模型池
3. strategy_result    → 各模型逐个判定结果，顺序检测进度动画
4. final_result       → 最终判定，数据包返回动画
```

## 数据模型设计

### 核心表关系

```
User (用户)
ApiKey (API 密钥)
SafetyTag (安全标签)
  ├── ModelTagLink ───▶ DetectionModel (检测模型)
  │                        ├── REST 配置字段
  │                        └── 脚本内容字段
  └── Strategy (策略编排)
         ├── StrategyModelLink ───▶ DetectionModel
         └── ApiPathStrategyLink ───▶ ApiPath (对外路径)

RequestLog (请求日志)
  └── DetectionLog (模型调用日志)
```

### 关键设计

- **标签 ↔ 模型**：多对多，一个检测模型可具备多种检测能力
- **策略 → 模型池**：多对多，策略从带同一标签的模型中选取组成检测模型池
- **路径 → 策略链**：有序多对多（`order_index`），按顺序执行

## 安全与隔离

### 1. 脚本沙箱

用户上传的 Python 脚本在独立子进程中执行：
- 主进程通过 `asyncio.create_subprocess_exec` 启动 Python 解释器
- 脚本与主服务进程完全隔离，死循环/崩溃不影响主服务
- 子进程设置超时，到期强制 kill

**进一步隔离建议**（生产环境）：
- 容器内运行，配合 cgroup 限制 CPU/内存
- 使用专用沙箱（如 Firecracker、gVisor）

### 2. REST 调用安全

- 使用 `httpx` 异步客户端并配置调用超时
- 默认不跟随重定向（降低 SSRF 风险）

### 3. 认证与权限

- 管理后台：JWT Bearer 令牌，`/api/auth/login` 获取
- 对外检测：API Key（`X-API-Key` 头），每个路径可绑定独立密钥
- 角色分离：`admin`（管理员）可管理用户，`operator`（操作员）仅操作业务

## 性能优化

### 1. 异步并发

- FastAPI 基于 ASGI，天然支持高并发
- 策略引擎基于 asyncio 异步调用模型，顺序检测期间不阻塞事件循环
- WebSocket 广播异步非阻塞

### 2. 数据库连接池

- SQLAlchemy 的 `sessionmaker` 配置连接池
- `pool_pre_ping=True` 自动检测死连接

### 3. 前端构建优化

- Vite 的懒加载路由（`() => import()`）
- ECharts 按需引入
- 生产构建开启压缩与分块

## 可观测与监控

### 日志层级

- `RequestLog`：每次对外检测请求，含最终结果与总耗时
- `DetectionLog`：每个检测模型的调用明细，含单模型耗时与判定状态

### 统计维度

- 累计请求数、安全/不安全计数
- 平均耗时
- 风险类型分布
- 近 7 日趋势

### 实时可观测

- 大屏通过 WebSocket 推送事件，0 配置即可监控
- 管理后台查询接口支持过滤与分页

## 扩展性

### 横向扩展

- 后端无状态，可部署多副本（负载均衡）
- WebSocket 广播在单实例内，多副本需引入 Redis Pub/Sub

### 纵向扩展

- 增加检测模型：在管理后台配置即可，无需修改代码
- 增加策略规则：在现有 sequential（顺序检测）与 random（随机检测）基础上扩展新的调用规则
- 增加安全标签：用户可自定义任意标签

### 接入外部系统

- 通过 REST 方式接入任意 HTTP 检测服务
- 通过脚本方式集成 Python 生态的安全工具（如 transformers 模型）

## 技术选型理由

| 技术 | 理由 |
|------|------|
| FastAPI | 原生异步、自动 OpenAPI 文档、类型安全 |
| SQLAlchemy 2.x | ORM 成熟、支持多数据库、2.x 异步友好 |
| Pydantic | 数据校验与序列化，与 FastAPI 深度集成 |
| Vue 3 | 组合式 API、轻量、生态完善 |
| ECharts | 开源图表库，适合数据大屏 |
| WebSocket | 实时推送，避免轮询开销 |
| PBKDF2 | 标准库实现，无需编译依赖（bcrypt 需本地编译） |
| Docker | 标准容器化方案，一次构建到处运行 |

## 未来优化方向

1. **分布式追踪**：集成 OpenTelemetry，追踪跨模型调用链路
2. **缓存层**：对高频相同内容的检测结果做短时缓存（Redis）
3. **A/B 测试**：同一路径配置多套策略，按流量比例分发
4. **模型性能画像**：统计各模型的准确率、耗时、稳定性，辅助策略配置
